# Tmux Terminals

一键恢复 Remote-SSH 断开后的终端工作区。

## 解决什么问题

用 VS Code Remote-SSH 时，连接一断，所有集成终端标签连同里面正在
跑的进程一起消失。重连后要手工重建每个终端、重新 `cd` 到各个工程
目录、重新敲一遍启动命令。

这个扩展在侧边栏维护一张终端清单。点一下，终端就回来了；如果远端
的 tmux 会话还活着，连**正在跑的进程和滚动历史**也一起接回来。

## 三个概念

- **终端**（侧边栏二级，也就是清单里的一条**条目**）：一份配置 —— 名称、
  远程目录 / profile / 模型（可选）/ 颜色 / 是否参与全部恢复。名称只用于显示，
  随时可改；它**不是** tmux 会话名。终端**没有自己的 tmux 进程** —— 进程
  属于它下面的每一个会话。终端也**没有**自定义命令字段：启动命令完全由
  `profile` 派生（见下）。
- **会话**（侧边栏三级，也叫**会话槽**）：一个 tmux 会话 + 它**永久绑定的
  那条 claude 对话**。一个终端下可以挂多个会话，它们共享该终端的
  profile / 模型 / 颜色，但各有各的进程与对话绑定。**tmux 进程易失、对话绑定
  持久**：进程没了（被关掉、远端重启）只表示这一行暂时没在跑，绑定还留着 ——
  再点它就能 `--resume` 接回**同一条**对话。会话的 tmux 名由槽 id 派生，形如
  `tmuxterm-<槽 id>`，所以改终端名称不会影响已建立的会话。
- **文件夹**（侧边栏一级）：按 cwd 精确分组的**虚拟**节点，没有独立实体 ——
  它是由终端清单里的目录自动算出来的。所以它的 `+` 只能把该目录当成新建终端
  时的默认值，不能「在文件夹里」存任何东西。

另外两个本文档常用的词：**存活** = 远端存在某个会话对应的 tmux 会话；
**接回** = 附到已存活的会话上，进程和历史都还在。

> 「**无会话**」在本扩展里只有**一个**含义：**三级行的标题占位符** —— 某个
> 会话拿不到任务名时，那一行就显示这四个字。它与「会话槽」这个数据结构无关
> （槽永远在，只是暂时没有名字）；「进程已死」与「活着但还没起任务名」都会
> 落到这四个字上，区分靠三级的图标（空心 = 无进程，实心 = 有进程）与 tooltip。

## profile：直连 / 中转

每个终端（条目）带一个 profile，决定用哪个 claude 入口启动、从哪读模型清单：

| profile | 启动命令 | 模型清单来源 |
|---|---|---|
| `ccr`（本地中转，默认） | `claude --dangerously-skip-permissions` | `~/.claude/settings.json` |
| `direct`（官方直连） | `claude-direct --dangerously-skip-permissions` | `/etc/claude/direct.json` |

profile 属于**终端**（二级），在行尾以**纯文本**显示：`中转` = `ccr`、
`直连` = `direct`。行首那条**小竖线**显示的不是 profile，而是你为这个终端挑的
**颜色**（未设颜色时是一条中性灰竖线）—— 颜色纯粹是给人看的标记，与 profile
无关。点「设置颜色…」时，列表里每一项前面就是一个**真实色块**（当前用的那一项
标着「当前」；当前色若是自定义 hex 会排到最前，是预设色则保持原序），所以不必
靠 `#rrggbb` 文本认颜色 —— 文本仍逐项留着，方便手抄与比对。两个词的完整含义
（`ccr（本地中转）` / `direct（官方直连）`）写在悬停的 tooltip 里。三级行上的
图标表示的是**进程状态**（空心 = 无会话，转圈 = 运行中，
实心绿 = 刚完成待查看），也不是 profile。

一个终端下的所有会话共享它的 profile：在三级上「切换直连/中转」或「设置模型」，
改的是**整个终端**，其下所有存活的会话都会用各自绑定的对话重启到新的
profile / 模型上。

旧版（v1）清单迁移时，命令里含 `claude-direct` 的条目映射为 `direct`，
其余映射为 `ccr`。

## 安装

需要在**已连接到远端**的 VS Code 窗口里安装，扩展才会装到远端。

```bash
npx @vscode/vsce package
# 产出 vscode-tmux-terminals-0.2.0.vsix
```

然后在远端窗口的扩展面板里选择「从 VSIX 安装」，挑上面那个
`vscode-tmux-terminals-0.2.0.vsix`。

> 本扩展声明了 `extensionKind: workspace`，必须运行在远端才能调用
> 远端的 tmux。装在本地是无效的。

## 使用

| 操作 | 效果 |
|---|---|
| 标题栏 `+` | 新建终端（依次输入 名称 → 目录 → 是否参与全部恢复；profile 默认 `ccr`） |
| 一级文件夹行尾 `+` | 在该文件夹的 cwd 下新建终端 —— 目录**直接继承**这一行的路径、**不再询问**（只问名称与是否参与全部恢复） |
| 点击二级（终端） | **展开 / 折叠**它的会话列表。二级**不再打开终端** —— 一个终端下可以挂多个会话，点它该开哪一个没有唯一答案 |
| 二级行尾 `+` | 新建一个会话。**零弹框**：名称、目录、profile、模型全部继承这个终端，不产生任何副作用（不会顺手起 claude） |
| 点击三级（会话） | 会话还活着 → 接回原进程（claude 还在跑就只接回，绝不打扰）；<br>claude 已退出 / 会话已死 → 重建并**接回这个会话自己那条对话** |
| 三级行尾 `X` | **关闭**这个会话：只杀掉它的 tmux 进程，**这一行会留下**（标题回落「无会话」），对话绑定原样保留 —— 再点它就是 `--resume` 接回**同一条**对话 |
| 标题栏 ⟳ | 恢复所有标记了「参与全部恢复」的终端的**每一个**会话 |
| 标题栏 ↻ | 只重查存活状态，不开终端 |
| 右键二级（终端） | 编辑 / 复制 / 设置颜色 / 设置模型 / 切换直连-中转 / 切换「参与全部恢复」 / 关闭该终端下全部会话 / 删除条目 |
| 右键三级（会话） | 上述条目级设置（**作用于整个终端**，确认框会点名范围）/ **选择要接回的对话…** / 关闭会话 / 删除会话 |

**三个「关闭 / 删除」不是一回事**，选错了损失完全不一样：

| 动作 | 入口 | 杀掉 tmux 进程？ | 这一行 / 这个条目还在？ |
|---|---|---|---|
| 关闭会话 | 三级行尾 `X` | 是 | **这一行还在**（绑定保留，再点它接回同一条对话） |
| 删除会话 | 三级右键 | 是 | 这一行不在了（对话绑定一起从清单里移除；对话记录文件本身不动，但扩展不再认得它） |
| 关闭该终端下全部会话 | 二级右键 | 是（每个会话都杀） | 终端条目与全部会话行都还在 |
| 删除条目 | 二级右键 | 是（**递归杀掉其下每一个会话**） | 整个终端连同它的全部会话一起消失 |

终端的启动命令不接受手输：它是 `profile` 的派生物（`ccr` → `claude`，
`direct` → `claude-direct`，若设了模型再带 `--model`）。要换启动方式就换
profile。

## 会话 ↔ 对话绑定

**绑定是会话级的属性**：每个会话槽自己存一个 `conversationId`，指它永久跟随的
那条 claude 对话，所以「**选择要接回的对话…**」挂在**三级**上。二级（终端）
没有唯一的对话，**二级没有、也不能有这一项** —— 同一个终端下的两个会话可以
各自绑着不同时间的对话，互不干扰。

每个会话**跟随它自己那条终端实际在跑的那条 claude 对话**：每次要接回之前先看
一眼终端（`pane_pid` → 后代里的 claude → 它自己的会话注册表），按观测结果把
**这个会话的**绑定刷过去，再用 `claude --resume <id>` 精确接回，不需要手动
`/resume`，多个会话共用同一个目录也不会串。所以你在某个会话的终端里 `/new`
开了一条新对话，**这个会话**的绑定也会跟着改绑过去 —— 不会在下次恢复时把那条
已经弃用的对话又接回来（同一终端下的**其他**会话绑的是它们自己的那条，
不受影响）：

- 新建会话（标题栏 `+` 建终端、或二级行尾 `+` 建会话）时会预分配一个
  「还没有对应记录」的对话 id，**首次启动**走一条**裸 `claude`**（不传任何
  会话参数）：此时还没有任何对话可接，当场开出来的那条就是这个会话的对话，
  随后的观测会把它记成绑定。**刻意不预先钉一个真实存在的 id** —— 那样只会
  在你眼前塞一个你没见过的会话，而它根本不会被用起来；
- 之后的每次恢复 → `claude --resume <id>`（`--resume` 按 cwd 作用域，
  而会话本来就是用终端目录建的，天然满足）；
- **老条目（本功能上线前建的，还没有绑定）** → 第一次需要接回时弹一次选择框，
  候选是该目录下的历史对话（显示 时间 / 首条用户消息原文 / 体积），
  选中即永久记住；
  列表末尾的「**＋ 新建一条对话**」用于明确地开一条新的；按 `Esc` 取消则
  **这次不启动 claude**（终端照常可用），下次再问；
- 随时可用三级右键「**选择要接回的对话…**」重新绑定；三级 tooltip 里能看到
  当前绑定的对话。**手动选的这条不会被下一次观测冲掉** —— 手动改绑只改「接回
  哪条」，不动「上次观测到的活跃会话」，于是下一次观测看到的还是同一条，
  等于没变化。唯一的例外是**终端自己换了对话**（你在里面 `/new`，或
  `/resume` 到另一条）：那是一条新的观测事实，绑定跟过去，手动选择让位；
- **首次启动不弹任何提示**；只有当这个会话**曾经真的跑起来过**、绑定的记录却
  不见了（被手动清理等）才会提示「本次新开一条，绑定会跟着新对话走」——
  前者是正常路径，后者才是真出了事；选中
  一条**已经绑给别的会话**的对话会弹确认（两个 claude 写同一条记录可能损坏
  它）—— 同一终端下的**兄弟会话**也算占用者，不确认就不接；
- 会话还活着、claude 还在跑时**只接回、不发送任何东西**；claude 已退出才会
  用 `--resume` 接回它自己那条。接不上时会明确报错，而不是默默退回裸 shell。

## 侧边栏的层级：文件夹 → 终端 → 会话

侧边栏是三级：**文件夹（按 cwd 分组）→ 终端 → 会话**，每一级各管一件事：

- **一级 文件夹**：标题是完整 cwd。行尾的 `+` 在该文件夹的 cwd 下新建终端
  —— 目录**原样继承**这一行的路径、**不再询问**，只问名称与是否参与全部恢复
  （标题栏的 `+` 仍会问目录，它没有可继承的文件夹）。
- **二级 终端**：行首一条**小竖线**显示你为它设的颜色（未设时为中性灰竖线），
  行尾显示 profile 的**纯文本** `直连` / `中转`（完整含义在 tooltip 里）。
  **点击它是展开 / 折叠**这个终端的会话列表，**不再打开终端**。行尾的 `+`
  新建一个会话（零弹框，继承这个终端的全部设置）。
- **三级 会话**：一行一个会话槽，标题是那个会话当前在做的**任务名**，拿不到
  任务名时显示「**无会话**」。**点它 = 接回 / 重建这个会话**。行尾的 `X`
  关闭它（只杀 tmux 进程，这一行会留下，再点就是接回同一条对话）。
  这一级**恒生成** —— 每个会话一行，不是「有任务名才出现」。

一个终端下可以挂**多个**会话，它们共享该终端的 profile / 模型 / 颜色，但各有
各的 tmux 进程与对话绑定、各占三级的一行。会话按清单里的 `order` 升序排列，
新建的追加在末尾。

三级上那个**任务名**的来源按优先级：

1. **实时 pane 标题**（权威）：claude 运行时会把自己的任务名写进终端标题，
   扩展剥掉前面的状态指示符后取来做名字；
2. **绑定对话的 `aiTitle`**（回退）：claude 不在跑（或没写标题）时，从该会话
   绑定对话的记录（`~/.claude/projects/**/<对话 id>.jsonl`）里读 `ai-title` 行；
   这条回退值是**后台异步读来的**，不是每次渲染现读：读不到时不会缓存成「没有」
   （刚 `/new` 出来的新对话要聊几个来回才生成 `ai-title`），而是按存活轮询的
   节拍**低频重试**（每条约 25 秒冷却一次），读到后立刻刷新侧边栏。所以刚
   `/new` 完的那一小段时间，那一行显示「无会话」是正常的，稍等它会自己变成
   任务名。
   而且**绑定本身也会按同一个存活轮询（默认 10 秒）的节拍被重新观测并纠正** ——
   读回退值之前，先确保读的是**当前**那条对话。所以刚新建会话、或者刚 `/new`
   之后，即使你**完全不碰侧边栏**，那一行也会自己跟上终端里真正在跑的那条
   对话。

3. **两个都没有 → 标题回落成「无会话」。** 三级行**不会**因此消失（槽还在，
   那一行是接回它的入口）。这是刻意的产品决定，不是待修的缺陷：宁可用一个
   如实的占位词，也不拿目录名之类「看起来像名字」的东西顶上 —— 把「不知道」
   伪装成「知道」会误导；回退来的名字也可能只是「上次那条对话的标题」，本来
   就不等于当前任务。「无会话」同时覆盖「进程已死」（空心图标）与「活着但还
   没起任务名」（实心图标），区分靠图标与 tooltip。

## 排序与批量操作

- **拖拽排序**：在「终端清单」里直接拖动终端条目即可重排。落点语义是「插到
  目标行之前」，拖到列表末尾 = 放到最后。**只允许同一个 cwd（同一个文件夹）
  内重排** —— 跨文件夹拖拽整体 no-op，什么都不发生。排序只改本地清单顺序，
  **绝不触发任何 tmux 操作**，也不影响已建立的会话。三级（会话）不支持拖拽，
  按 `order` 升序显示。
- **批量操作**：面板按**文件夹分组**：一级标题是**完整 cwd**，二级才是终端
  条目（只列二级，**不显示三级** —— 会话是终端的一部分，批量命令作用的对象
  是终端）。点击二级条目切换它自己的选中态（实心勾 = 已选，空心圈 = 未选）；
  **点击一级标题**则整组一起选 / 取消：已全选时点一下 = 全不选，其余情况
  （未选 / 部分选中）点一下 = **补齐成全选**（部分选中时点一下的意图是
  「补齐」，这是列表类界面的通行语义）。标题栏三个按钮把选中条目统一
  「设为中转 / 设为直连 / 批量设置模型」，一个终端下的所有会话会一起变。

## 重要：启动命令只在「新建会话」时执行

会话还活着时，点击是**接回**，由 profile 派生的启动命令**不会**执行 ——
你看到的是会话里原有的进程。

这是刻意的：如果往一个正在运行的会话里发命令，那行命令会作为键盘
输入进入你正在跑的进程（比如一个 claude、一个编译、一个 REPL），
后果不可预料。

想按 profile 重新启动一次，先关掉这个会话（三级行尾 `X`，或二级右键「关闭该
终端下全部会话」），再点那一行 —— 重建时会按 profile 派生的命令启动，并
`--resume` 接回它自己那条对话。

## 配置

| 配置项 | 默认 | 说明 |
|---|---|---|
| `tmuxTerminals.pollInterval` | `10000` | 存活状态轮询间隔（ms），`0` 关闭 |
| `tmuxTerminals.tmuxPath` | `tmux` | tmux 可执行文件路径 |
| `tmuxTerminals.storagePath` | `""` | 清单文件路径。留空用扩展存储目录，**重装扩展会清空** |

## 已知副作用：运行中切模型会改全局默认

- **未运行**的会话：切模型只改**终端**的配置（模型存在二级，一个终端下的
  会话共享），下次打开时经 `--model` 启动参数带出，**不污染**全局默认。
- **运行中**的会话：切模型会给该终端下**每一个存活的会话**发送
  `/model <目标>`，立即生效（重启会丢对话，命令行 `--model` 也盖不过
  resumed 会话，故必须用 `/model`）。这会**顺带改写**
  `~/.claude/settings.json` 里的全局默认模型。这是「立即生效」的代价，
  扩展如实照做、不试图规避 —— 若不想动全局默认，请在会话空闲时切或事后
  手动改回。
- **激活时会观测并可能改绑**：扩展激活（以及面板变可见、展开节点、点 ⟳、
  以及**每 10 秒的存活轮询**）都会看一眼每个会话「在跑哪条对话」，绑定与观测
  不符就写回清单 —— 于是**重载一次窗口就会让清单文件（`terminals.json`，或
  `storagePath` 指定的那个文件）的 mtime 变化**，哪怕你没有做任何操作。这是
  刻意的（激活与轮询都是既定的触发点），但它与 `src/core/store.ts` 里「打开个
  扩展就改了用户文件」是不可接受的副作用这一原则**存在张力**，故在此显式
  说明。
  需要区分的是：**稳态下不写盘** —— 只有当观测到的活跃对话与已存绑定**不一致**
  时才会回写。绑定已经收敛的那些会话，每次观测都判为「没变化」，清单文件一个
  字节都不会动。

## 从旧版（0.1.x）升级

清单格式从「一条目 = 一个会话」换成了「一条目 = 会话槽数组」。升级是**无损且
自动**的：第一次加载旧清单时就地升成新格式（每个旧条目补一个会话槽），
**槽 id 就等于原来的条目 id** —— 所以旧版本建的 tmux 会话
（`tmuxterm-<条目 id>`）照样认得出，正在跑的进程与对话绑定一个都不丢；
旧的每个条目就变成**一个会话**（三级的一行）。清单文件本身则在**下一次写入**
时被改写成新格式。

升级前会先把原文备份到清单文件旁边：`terminals.json.v2.bak`（与 v1 的 `.bak`
并列、互不覆盖）。万一要回退，把它换回原名即可。

## 已知限制

- 条目按远端机器隔离（扩展在每台远端各存一份清单）。
- 远端没装 tmux 时仍能开终端并 `cd`，但没有接回能力。
- 远端机器重启过则所有 tmux 会话消失，所有会话行回落成空心圆（点击即重建
  并接回各自的对话）。
