# 手动冒烟清单

纯逻辑层有单测覆盖，但 VS Code 接线层没有自动化测试。装好后请逐条
走一遍。

## 准备

在一个**已连接远端**的 VS Code 窗口里装好 `.vsix`，重载窗口。

## 清单

- [ ] 侧边栏出现「我的终端」图标，点开显示空清单与「点击 + 添加」
- [ ] 点 `+`，依次输入 名称 `smoke-a`、目录 `~`、是否参与全部恢复选「是」。
      条目默认 `ccr` profile —— **无需也不能输入启动命令**，命令由 profile 派生。
- [ ] 一级出现该目录（完整 cwd），其下是 `smoke-a`；`smoke-a` 下面**已经
      有一行三级**，标题是「无会话」（新建终端时预分配了一个还没有记录的
      对话 id，此刻没有任务名可显示）
- [ ] 二级行首是**一条中性灰竖线**，行尾显示 profile 的纯文本 `中转`
      （`ccr` 的默认）—— 不是目录、不是「无会话」、不是图标
- [ ] 点击**三级那一行** → 终端打开、位于家目录、tmux 会话建立；会话里
      **按 profile 启动 claude**（`ccr` 下即 `claude --dangerously-skip-permissions`，
      direct 则 `claude-direct …`）。可在终端里 `tmux ls` 确认会话
- [ ] 三级行的图标从空心圆变成**实心圆**（claude 在干活时会转圈）
- [ ] 再点一次三级那一行 → 复用已有终端，不新开
- [ ] **核心验证**：在该终端里运行 `sleep 600`，然后断开 SSH →
      重连 → 点三级那一行 → 接回后 `sleep 600` **仍在运行**
      （用 `Ctrl-C` 打断它验证确实是同一个进程）
- [ ] 右键**二级** → 「关闭该终端下全部会话」→ 确认 → 三级行图标转回空心圆，
      **那一行还在**（标题仍是「无会话」）
- [ ] 再次点击三级那一行 → 重新建立会话并 `--resume` **接回它自己那条
      对话**，**启动命令按 profile 重跑一次**（若前台是 claude，应能看到它
      重新起来）
- [ ] **前缀安全**：建两个终端 `smoke-b` 和 `smoke-b-long`，都打开。
      对 `smoke-b` 右键「关闭该终端下全部会话」，确认 `smoke-b-long` 的
      三级行仍是实心圆（验证精确匹配，没有被前缀误杀）
- [ ] **全部恢复**：删除 `smoke-b-long`，右键 `smoke-a` 与 `smoke-b` 的
      二级行确认参与全部恢复，点标题栏 ⟳ → 两个终端的**每个会话**都被拉起
- [ ] 右键二级 → 编辑 → 改目录 → 点三级那一行确认新目录生效
- [ ] 右键二级 → 复制 → 出现 `smoke-a-copy`
- [ ] **删除条目会递归杀会话**：在 `smoke-a` 下建 2 个会话并都打开 →
      右键**二级** → 删除条目 → 确认框里**点名会话数**
      （「它下面的 2 个会话都会被一并杀掉」）
      → 确认后条目连同它的会话行一起消失，且 `tmux ls` 里
      `tmuxterm-<这两个槽 id>` **都没了**（0.1.x 的行为是「tmux 会话仍在」，
      本轮反过来了）
- [ ] **无 tmux 降级**（可选）：把 `tmuxTerminals.tmuxPath` 改成一个
      不存在的路径 → 所有三级行图标变空心圆（三级行本身仍在），
      点击仍能开终端并 `cd` 到目录

## v2 增补项（排序 / 批量 / 模型切换 / 杀会话）

- [ ] **拖拽排序持久**：在「终端清单」里把某个终端拖到别处 → 顺序变化，
      且 `tmux ls` 输出**不变**（排序绝不触发任何 tmux 操作）。重载窗口
      后顺序仍保持。**再试一次跨文件夹拖拽**（把一个终端拖到另一个 cwd 的
      分组里）→ 什么都不该发生。
- [ ] **关掉会话 ≠ 丢掉对话（X 的语义）**：点三级行尾的 `X` → 确认 →
      对应终端面板关闭、那一行**还在**、标题回落「无会话」；**再点那一行
      接回的是同一条对话**（不是新开一条）—— 若接回来是一条全新对话，
      说明关闭时顺手清掉了绑定。
- [ ] **运行中的 claude 切模型**：在某个会话的终端里跑起 `claude`，
      右键**二级**「设置模型…」选一个 → 会话里的模型立即生效，二级的
      tooltip「模型」字段更新为该模型。**该终端下的每个存活会话都要变**
      （多开一个会话再切一次，两个会话都应生效）。
- [ ] **运行中的非 claude 切模型 → 必须拒绝**：在该终端里运行
      `sleep 600`，右键「设置模型…」→ 必须弹出「已拒绝」错误
      （前台进程不是 claude），且 `sleep` 进程不受影响。
- [ ] **批量设为直连**：在「批量操作」面板选中 2 条 → 标题栏「设为直连」
      → 这两条的行尾由 `中转` 变成 `直连`（悬停 tooltip 也应变成
      `direct（官方直连）`）。

## 会话身份增补项（**必须手动** —— 自动测试覆盖不到）

> **为什么只能手动**：`test/e2e-harness.js` 是把 `TerminalManager` 直接
> `new` 出来跑的，**从不加载 `src/extension.ts`**（单测同理）。所以本批加在
> extension.ts 里的 **5 个 reconcile 触发点**、以及活动采样闸门，
> **没有任何自动化覆盖**，只能由人在这里走一遍。
>
> 下列观察点都对准本批修的两个症状：
> **(a)** 在 claude 里 `/new` 换了会话（或手动改绑）后，条目**存着**的对话
> 要跟着终端走 —— 修复前它一直停在换掉的那条上；
> **(b)** 第三级「任务名」要在面板一可见就出现（**约一拍 ≈900ms** ——
> 该拍长源自 `extension.ts` 的 `ACTIVITY_POLL_INTERVAL_MS`，**是代码推断、
> 未经实测**），而不是等默认 **10s** 的存活轮询。

> **与 0.2.0 的差异（先读，否则下面每条都会看错）**：绑定现在是**会话级**的，
> 所以「存着哪条对话」要悬停**三级行**看，二级的 tooltip 里**没有**「对话：」
> 这一行（一个终端下可能有好几个会话，二级没有唯一答案）。三级那一行也**恒在**，
> 不再是「有任务名才多出一层」—— 要判断的变成「标题是任务名还是『无会话』」。

**两个观察窗口**（每条都要用，先记住怎么看）：

- **这个会话存着哪条对话**：鼠标悬停在**三级那一行**上，tooltip 里以「对话：」
  开头的那一行显示的就是这个会话**当前存着**的对话 id —— 只给前 8 位、后面跟
  `…`，并附「启动时接回这条」。那一行若显示「未绑定」，即表示没存。
- **三级任务名**：三级那一行的**标题**。标题是「无会话」= 此刻没有可显示的
  任务名；变成别的字 = 有名字了。它优先取 tmux pane title 解析出的任务名，
  解析不出时才回退到**绑定对话的 aiTitle** —— 两种来源都会让它出现/变化。
  第三级只读内存缓存，**重载窗口即清空**（想让它从「没有」开始，先重载窗口）。

### reconcile 的触发点（六条；源码 `extension.ts:138-140` 枚举的是**五个**，「展开树 / 面板可见」在下面拆成了 ④⑤）

- [ ] **① 扩展激活**：先确认这个会话**已绑定**一条对话（悬停三级行，「对话」
      行不是「未绑定」）、且它的 tmux 会话里 claude 正在跑。然后用
      `Developer: Reload Window` 重载窗口，**不碰 ⟳、不点任何一行**，
      等约一秒：三级行的**标题**应已变成任务名（而不是停在「无会话」）；
      悬停三级行的「对话」行，短 id 应与终端里 claude 正用着的那条一致
      （若重载前刚 `/new` 过，这里应已自动跟上，无需手动操作）。
- [ ] **② ⟳ 刷新**：先在终端里让 claude `/new` 换一条会话并随便说两句
      （或用下面的「手动改绑」改一次）。回侧边栏点标题栏 ⟳「刷新状态」。
      **命令返回时（转圈结束）**悬停三级行，「对话」行**已经**变成终端当前
      那条 —— 这一步是同步的，不需要再等。三级标题随下一拍刷新。
- [ ] **③ 点击三级行**：在 ② 之后，右键**二级**「关闭该终端下全部会话」→
      三级行图标转空心 → 点击三级行重建。**接回/重建的必须是当前那条新
      对话**（不是 `/new` 之前被放弃的那条）；悬停三级行的「对话」行与之一致。
- [ ] **④ 面板变为可见**：把侧边栏切到别的视图（如「资源管理器」），再切回
      「Tmux Terminals」。**约一拍（≈900ms）内**三级标题就应出现/刷新
      （该拍长源自 `ACTIVITY_POLL_INTERVAL_MS`，未经实测）；
      **不应**拖到默认 10s 的存活轮询才动。
      *（更尖的判据，可选）：临时把 `tmuxTerminals.pollInterval` 调大到
      `30000`，重载窗口后重复本步 —— 三级标题**仍应在约 1s 内**出现/刷新。
      若它跟着变成 30s 才动，说明它走的是存活轮询而不是活动采样闸门。*
- [ ] **⑤ 展开节点**：把已展开的文件夹节点**折叠**、再**展开**；或展开一个
      默认折叠的节点。展开这一下本身即触发 reconcile —— 悬停三级行的
      「对话」行应立刻跟随终端当前会话，三级标题随下一拍出现。
- [ ] **⑥ 切 profile**：右键**二级**（或三级）→「切换直连/中转」，把它从
      `ccr` 切到 `direct`（或反向）。**切之前先在这条会话里 `/new` 换一条
      对话**，再执行切换。切完悬停**二级**：tooltip 的「profile：」行应已翻转
      （`ccr（本地中转）` ↔ `direct（官方直连）`，行尾的 `中转` / `直连`
      也随之变），悬停**三级**：「对话：」行应是 `/new` 之后那条**新**对话
      —— 切 profile 会先 `/exit` 再用 `--resume` 重启 claude，
      **绝不能接回被放弃的旧对话**。
      （`restartClaude` 正是在 `--resume` **之前**先 reconcile，
      所以这条路径正是「绑定一旦陈旧就接回旧对话」的现场。）

### 核心：绑定跟随 + 手动改绑不被冲掉

- [ ] **★ `/new` 之后绑定自动跟随**（本批的主症状）：
      在某个会话的终端里跑起 claude → 悬停**三级行**记下「对话」短 id
      （记作 **A**）→ 在 claude 里输入 `/new` 开一条新对话，随便说两句
      → 回侧边栏点 ⟳ → 悬停**同一行**，「对话」应变成 **B（≠ A）**，
      且 B 是该目录下**最新**的那条对话（三级右键「选择要接回的对话…」的
      列表里，最新一条就是它）。**同一终端下的另一个会话必须不受影响**
      （它绑的是它自己那条）。
      **修复前的表现**：这里仍显示 A，且恢复时会接回被放弃的 A。
- [ ] **★ 手动改绑要守得住**：右键**三级行** →「选择要接回的对话…」→ 选一条
      **不是**最新、也不是终端当前在用的对话（记作 **X**）→ 悬停该三级行应显示
      X 的短 id。再点 ⟳、并把侧边栏切走再切回。**X 必须保持不变** ——
      手动选择不能被下一轮观测冲掉。
      （例外：若这期间终端里真的又 `/new` 过，那属于「终端换了会话」，
      X 应当让位给新会话 —— 那正是上面那条的行为。）
- [ ] **★ 兄弟会话也算占用者**：同一终端下开两个会话，把槽 1 绑到对话 C
      （用三级右键「选择要接回的对话…」手动选一条**非最新**的）→ 再给槽 2
      打开同一个选择框 → 候选里 C 那行**应标出「已绑给「<终端名>」」**；
      选中 C 时**必须弹二次确认**，拒绝确认则绑定不变、什么都没启动。
      （若 C 在这里既没标记、选了也不问，说明归属判据又按条目摊平了 ——
      后果是两个 claude 同写一条 `.jsonl`。）

## 选择框噪音 / 首启参数 / 三级刷新（2026-09-16 增补）

> 同样只走手动 —— 单测覆盖了纯函数层（`isSyntheticUserText`、
> `parseConversationHead`、重试冷却与通知），但「QuickPick 里到底显示成什么样」
> 和「首启那条命令行长什么样」都要真机看一眼。

- [ ] **合成包裹消息不再进选择框**：在任一终端里先输入 `/clear`（或让该会话
      以任何斜杠命令开头）→ 再右键**三级行** →「选择要接回的对话…」。
      列表里**不应**出现 `<local-command-caveat>`、`<command-name>` 这类尖括号
      文本；该会话那行要么是它**真正的**首条提问，要么是「（无首条消息）」。
      整列扫一遍确认。
- [ ] **★ 选择框必须能弹出来**：右键任一已打开过的**三级行** →「选择要接回的
      对话…」→ 列表**必须立刻出现**。**修复前的表现**：命令直接报错
      `CANNOT use API proposal: quickPickItemTooltip`，列表根本不弹（原因：
      `QuickPickItem.tooltip` 是 proposed API，正常安装的扩展用不了）。
      同一处一旦抛错，老会话首次接回、全部恢复、切 profile 也都会跟着失败 ——
      它们走的是同一个选择框。
- [ ] **候选显示的是一行，内容是首条提问的原文**：列表里每条候选是
      `时间 · 首条用户消息原文 · 体积`，**只有这一行**——没有第二行、
      也没有悬停浮层（`QuickPickItem.tooltip` 是 proposed API，正常安装的
      扩展用不了，用了会让整个选择框抛错）。原文**不压缩语义**，只把换行
      压成空格；超长由 VS Code 按行宽自己截断成 `…`。挑一条你记得的会话，
      确认显示的就是你当时敲的那句话（而不是被改写过、或截到 60 字的版本）。
- [ ] **「+」新建的首启不带会话参数**：标题栏 `+` 建一个终端（或二级行尾 `+`
      建一个会话）→ 点三级那一行打开。**不应**再弹「绑定的对话还没有记录…」
      那条提示；终端里起来的是一条全新对话（不是接回任何历史）。聊一句之后
      悬停该三级行：「对话」行短 id 应当**变成**这条新对话的 id —— 这说明
      绑定是被观测回写的，而不是出生时钉死的那个。
- [ ] **★ 三级任务名会自己出现，不用点 ⟳**：在某个会话里 `/new`（此时那一行
      的标题会回落成「无会话」，正常 —— **那一行本身不会消失**）→ **之后不要
      点任何一行、也不要点 ⟳**，就在这个终端里聊两三个来回等 claude 写出
      `ai-title`。最多约 **35 秒**（存活轮询 10s + 缓存内 25s 冷却，最坏情况
      各差一拍）内，三级标题应当**自己**变成任务名，并且二级是**展开**状态。
      若不出现，先确认 `tmuxTerminals.pollInterval` 没被设成 0，且面板当时是
      可见的（隐藏时不轮询）。

## 存活轮询自动观测（2026-09-16 增补）

> 本批把 reconcile 挂上了 10 秒的存活轮询（`src/extension.ts` 的 `poll()`）——
> 从此**不碰面板也会自动观测并改绑**。这三条都只能手动看：`extension.ts`
> 不参与任何自动化测试（见上一节的说明）。

- [ ] **★ 完全不碰面板，三级标题自己变成任务名**（本批主症状，必须走这条）：
      标题栏 `+` 新建一个终端 → 点它的三级行打开终端 → 在终端里向 claude 提
      两三个问题（聊到它写出 `ai-title`）→ **之后完全不碰侧边栏**：不点任何
      一行、不点 ⟳、不折叠也不展开任何节点，连鼠标都不要移到侧边栏上。
      等约 **10~35 秒**（存活轮询 10s + 缓存内 25s 冷却，最坏情况各差一拍），
      观察**看哪里**：三级那一行的标题。**应该看到**：标题变成**你刚在聊的
      那个任务**的名字，而不是重载窗口前的旧名字、也不是「无会话」。
      **不该看到**：标题一直停在「无会话」、或显示的是别的（旧的）任务名。
      **修复前的表现**：标题永远不出现 —— 绑定停在新建时预分配的幽灵 id 上，
      回退链每 25 秒去重读一个不存在的文件。
      （若没出现，先确认 `tmuxTerminals.pollInterval` 没被设成 `0`，且侧边栏
      当时**可见** —— 面板隐藏时这一拍不跑，属正常。）
- [ ] **标题栏没有常驻进度条**：保持侧边栏面板可见，盯住视图标题栏那行约
      半分钟。**应该看到**：标题栏是静止的（只有图标），没有一直在转的进度条。
      **不该看到**：标题栏上挂着一个永不停的 spinner —— 那说明某一拍被拖成了
      「永远没跑完」。本批新增的 reconcile 与既有的存活查询共用一次轮询，
      正常时它几分之一秒就结束。
- [ ] **连点几个会话不卡顿**：快速连续点击 3~4 个不同会话的三级行（每个点完
      立刻点下一个，不等终端起来）。**应该看到**：每点一个，对应的终端
      **立即**被切到前台。
      **不该看到**：点完当下没反应、过几秒才把刚才点过的终端**一次性全跳
      一遍** —— 那说明点击被排进了某个串行的队列里干等（观测应当在点击返回
      前就结束，不该把按键攒起来补发）。

## 0.2.2 增补项（切模型 / 切 profile：一个坏会话不再拖累其余）

> 一个槽已经退回 bash，导致这三个条目 100% 复现。修复只改「跳过 vs 拒绝」
> 这一条，§7.5「三级转发到整个条目」的语义**不变**。

- [ ] **★ 部分槽跳过、其余照常生效**：一个终端挂 3 个会话，其中 1 个在

      未在跑 claude，已跳过」，且**另外 2 个**会话的模型立即生效、二级

      中转」同理（跳过的槽不会被重启，其余槽正常重启并接回各自的对话）。
- [ ] **★ 全部槽都不是 claude → 直接落配置、下次启动生效（0.2.3 起）**：

## 0.2.5 增补项（可观测性 / 韧性）

> 背景：本批不改功能语义，只补「出问题时看得见」这条链路。此前这个扩展的失败
> 大多表现为**沉默** —— 面板在、命令点不动、任务名一直「无会话」，却没有任何
> 地方告诉你卡在哪一环。本批新增了一条 Output 面板通道与若干失败路径的日志，
> 下面每一条都是「照着日志核对」的手动动作。
>
> 为什么每行都带 `[时间 pid=<进程号>]`：这个窗口的**扩展宿主会被反复重建**，
> 而输出面板是**跨宿主累积**的。同一个命令名、同一段文案在每一代宿主里都一模
> 一样，**只有 pid 能告诉你这一行出自哪一代** —— 读日志时先看 pid 有没有变。

### 日志面板：激活时该看到什么

- [ ] **通道存在**：菜单「查看 → 输出」，在右上角下拉里选中「TMUX 终端」。
      **应该看到**：这个通道存在（不依赖是否触发过任何操作）。
- [ ] **★ 激活那几行齐全**：`Developer: Reload Window` 重载窗口，然后逐条核对
      下面这几行都出现了（顺序如下，值随你的配置而变）：
      - `[时间 pid=P] 扩展激活开始`
      - `[时间 pid=P] 生效配置：tmuxPath=…，pollInterval=…，storageFile=…`
        （`pollInterval` 默认 10000；`storageFile` 是清单文件路径）
      - `[时间 pid=P] 存活轮询已启动：间隔 10000ms`
        或 `存活轮询未启动：pollInterval=…（<=0 = 关闭），view.visible=…`
      - `[时间 pid=P] 活动轮询已启动：间隔 900ms`
        或 `活动轮询未启动：view.visible=…`
      - `[时间 pid=P] 激活完成：已注册命令 N 条，view.visible=…，总耗时 …ms`
        （`N` 应等于 `package.json` 里注册的命令数，**不是 0**）
      - `[时间 pid=P] 标题缓存已从磁盘恢复`（仅在 `task-titles.json` 存在且可读时出现）

### 命令进没进来：进入 / 完成两行

- [ ] **点任意一个条目/按钮，日志里有两行**：随便点一个二级行尾 `+`、或点标题栏
      ⟳「刷新状态」，回到「TMUX 终端」通道。**应该看到**成对的
      `命令 <id> 进入，实参形状=[…]` 与 `命令 <id> 完成，耗时 …ms`。
- [ ] **★ 实参形状不是 `undefined`**：上面那句「进入」里方括号里的内容**不能是
      `undefined`**。若是 `undefined`、而这次操作又没有任何反应，说明
      **`instanceof` 守卫没命中** —— 命令确实被调用进来了，但实参不是期望的
      `TreeItem` 类型，于是守卫静默放行、什么都不做。这一行正是为了把
      「命令压根没进来」与「进来了但被守卫挡下」这两种沉默区分开。
- [ ] **失败路径**：构造一次失败（例如对一个从未绑定过对话的槽切 profile），
      日志里应是 `命令 <id> 失败，耗时 …ms` **外加异常栈**，并弹一条错误提示
      **指向日志面板**（不再是只弹一句没头没尾的话）。

### 面板可见性：两个轮询的开关

- [ ] **切走再切回，各有一行**：把侧边栏切到别的视图（如「资源管理器」），再切回
      「我的终端」。日志里**应该看到** `面板可见性变化：visible=false` 紧接着
      `面板可见性变化：visible=true`。
- [ ] **★ false 那一次紧跟着两条「未启动」**：切走（`visible=false`）之后，紧接着
      应该出现 `存活轮询未启动：pollInterval=…（<=0 = 关闭），view.visible=false`
      与 `活动轮询未启动：view.visible=false` 两条。
      **为什么这条最要紧**：存活（10s 一拍）与活动（900ms 一拍）两个轮询**都只在
      `view.visible === true` 时才装定时器**。如果切回来之后 `view.visible` 仍是
      `false`（例如日志里只有 false、没有 true），两个轮询都不会跑、采样永远攒不
      起来，外表就是**任务名一直显示「无会话」**。这是排查该症状的**第一站**。

### 标题缓存落盘（宿主重建后的快速恢复）

- [ ] **★ 重载后三级任务名立刻出现**：确认某个三级会话有任务名后，用
      `Developer: Reload Window` 重载。**应该看到**三级标题**立刻**就是任务名，
      **不必等 10 秒**的存活轮询；日志里有 `标题缓存已从磁盘恢复`；且 globalStorage
      目录下存在 `task-titles.json`。
- [ ] **删掉该文件也是安全的**：删掉 `task-titles.json` 再重载。**应该看到**任务名
      经历「先回落成『无会话』、再由轮询回填」的过程 —— 这说明删除只失去那一次
      快速恢复，缓存会从零重新预热，**没有别的副作用**。写入走原子改名，中途被
      打断也不会留下半截文件。

### 失效时怎么读日志

日志停在不同的地方，对应完全不同的故障层，先按这四种分辨：

1. **停在 `扩展激活开始` 那几行、且 pid 之后再没变过** → **宿主级问题**：
   `activate` 没往下走完（或扩展宿主自身起不来）。这类问题不在扩展逻辑里，
   看宿主 / 环境。
2. **`激活完成：已注册命令 0 条`** → **激活中途抛了异常**：所有命令都没注册，
   外表是「面板看得见但点什么都没反应」。异常本身现已被记进日志并弹错误提示
   （从前是静默的）。
3. **有轮询日志但不再增长** → **轮询停摆**：看有没有那条超时的 error/warn。
   本批给两个轮询都加了**有界超时**（存活 **15 秒**、活动 **8 秒**），超时会强制
   释放闸门并记录 —— 从前 tmux 客户端卡住一次，`inFlight` 闸门会**永久停在
   `true`**，轮询从此静默停摆。同一批还让 `TmuxClient` 的每个 tmux 子进程调用都
   带 **5 秒超时（SIGKILL）**，不再可能永不返回。
4. **点了命令，日志里完全没有「进入」那行** → **命令压根没被调用到**：
   问题在调用链上游（按钮没接线、`when` 条件没命中），而不是命令体内部。

## 0.2.6 增补项（多会话面板身份修复）

> 背景：面板身份过去是**按条目名**认的，不是按**槽**。`terminalManager.ts` 的
> `candidatePanel` 在内存 Map 未命中时会用 `window.terminals.find((t) => t.name === name)`
> 按**显示名**捞面板，而所有面板都拿 `entry.name` 当名字 —— 同一个条目下 N 个槽
> 的面板名**完全相同**。于是点第 2 个起的槽时捞到的是第 1 个槽的面板，
> `core/restore.ts` 的 `decideOpen` 见「会话存活 + 有客户端附着 + present」直接判
> `'show'`，`openSession` 把**别人的**面板 show 出来就 return 了 ——
> **真正该建的那个面板永远不会被建**。这是 v3 多会话引入的回归：v1/v2 一个条目
> 只有一个会话，`entry.name` 天然唯一，撞不上；而规格
> （`2026-09-16-multi-session-design.md`）里**从未规定过面板身份**，属规格缺口。
>
> 修法：新增纯函数 `src/core/panels.ts#panelNameFor(entry, slot)`，把面板名
> **按槽唯一化** —— 单槽条目（含 0 槽）**原样**返回 `entry.name`，一个字符都不加；
> 多槽条目返回 `` `${entry.name} · ${slot.id.slice(0, 4)}` ``（分隔符是前后各带一个
> 空格的 ` · `，取槽 id 前 4 位，例：`新点子落地 · 251c`）。`candidatePanel` 另加
> 一道不变量守卫：**同名终端若已被映射给别的槽，就不认它**，宁可让上层新建一个
> 正确的面板。**为何单槽不加后缀**：单槽是绝大多数情形，`entry.name` 本来就唯一，
> 加一截随机串纯粹是标签噪音，用户还得从标签上认出这是哪个终端。**为何靠名字而
> 不是别的字段**：VS Code 不允许给终端挂扩展自定义数据，宿主重载后内存 Map 已
> 清空、`window.terminals` 里只剩 `name` 可查 —— 名字是唯一能跨宿主认回面板的
> 依据。

- [ ] **★ 多会话下逐个点击、各跳各的（本批主症状）**：找一个二级行下挂着
      **≥2 个会话**的条目，**逐个**点它下面的**每一个**三级行。
      **应该看到**：每点一个，打开的都是**各自独立**的终端，分别接回**各自**那条
      对话（逐个悬停三级行的「对话：」行，短 id 各不相同，且与各自终端里 claude
      实际在用的那条一致）；**第二个起也有反应**。
      **不该看到**：不管点第几个，打开的永远是第一个终端。
      ⚠ **修复前的表现是「只有第一个能跳、其余点了没反应」** —— 第 2 个起的槽被
      误判成「第 1 个槽的面板还在，show 它就完事」，真正该建的面板从未被创建
      （不是「点不动」，是压根没走到建面板那一步）。
- [ ] **终端标签页的命名规则**：单槽条目的终端名**与条目名一模一样**（没有任何
      后缀、分隔符或随机串）；多槽条目的终端名形如 `新点子落地 · 251c` —— 即
      `条目名` + ` · ` + **槽 id 前 4 位**（分隔符 ` · ` 前后**各一个空格**）。
      对照着侧边栏改名再点一次，新建出的面板应带**新**名字与同一个槽后缀；
      已经开着的旧面板不会自己重命名（终端名只在创建时定），属既有行为。
- [ ] **升级后的一次性清理**：若你在旧版本（0.2.5 及以前）下已经有**一批同名的
      多会话终端**，它们**不会被复用** —— 名字对不上新规则（`条目名 · xxxx`），
      所以升级后第一次点各自的槽会**各自新建一个**面板，而旧的那批同名终端仍留
      在标签栏里（旧的、第一次点过的那些槽也会各自多出一个旧名面板）。
      **手动关掉那批旧的同名终端**即可，之后不再出现（关掉只是清掉残留的面板，
      tmux 会话与对话绑定一概不受影响）。
- [ ] **反例守卫：撞名也不再被误认领**：即使因为历史原因确实存在一个**和本槽
      期望名完全相同**、但实际属于别的槽的终端，`candidatePanel` 也不会把它认成
      本槽的 —— 它已被映射给别的槽，守卫判成「不是这个槽的」，转而**新建正确的
      那一个**。**应该看到**：点这个槽后新建出一个面板、并接回**本槽自己**那条
      对话，而不是跳到那个撞名的终端上。
