# 手动冒烟清单

纯逻辑层有单测覆盖，但 VS Code 接线层没有自动化测试。装好后请逐条
走一遍。

## 准备

在一个**已连接远端**的 VS Code 窗口里装好 `.vsix`，重载窗口。

## 清单

- [ ] 侧边栏出现「我的终端」图标，点开显示空清单与「点击 + 添加」
- [ ] 点 `+`，依次输入 名称 `smoke-a`、目录 `~`、是否参与全部恢复选「是」。
      条目默认 `ccr` profile —— **无需也不能输入启动命令**，命令由 profile 派生。
- [ ] 侧边栏出现 `smoke-a`，圆点为 ⚪，描述显示目录 + 「无会话」
- [ ] 点击该条目 → 终端打开、位于家目录、tmux 会话建立；会话里
      **按 profile 启动 claude**（`ccr` 下即 `claude --dangerously-skip-permissions`，
      direct 则 `claude-direct …`）。可在终端里 `tmux ls` 确认会话
- [ ] 圆点变为 🟢
- [ ] 再点一次该条目 → 复用已有终端，不新开
- [ ] **核心验证**：在该终端里运行 `sleep 600`，然后断开 SSH →
      重连 → 点 🟢 条目 → 接回后 `sleep 600` **仍在运行**
      （用 `Ctrl-C` 打断它验证确实是同一个进程）
- [ ] 右键该条目 → 「杀掉远端 tmux 会话」→ 确认 → 圆点转 ⚪
- [ ] 再次点击 → 重新建立会话，**启动命令按 profile 重跑一次**
      （因为这次是新建；若前台是 claude，应能看到它重新起来）
- [ ] **前缀安全**：建两个条目 `smoke-b` 和 `smoke-b-long`，都打开。
      杀掉 `smoke-b`，确认 `smoke-b-long` 仍为 🟢（验证精确匹配，
      没有被前缀误杀）
- [ ] **全部恢复**：删除 `smoke-b-long`，右键 `smoke-a` 与 `smoke-b`
      确认参与全部恢复，点标题栏 ⟳ → 两个终端都被拉起
- [ ] 右键条目 → 编辑 → 改目录 → 点开确认新目录生效
- [ ] 右键条目 → 复制 → 出现 `smoke-a-copy`
- [ ] 右键条目 → 删除条目 → 确认 → 条目消失，
      但 tmux 会话仍在（`tmux ls` 里还能看到）
- [ ] **同目录短标签**：建两条目录都填 `~` 的条目 → 两行的描述都显示
      为 basename（`<家目录名>`，如 `qiansenwei`）而**非完整路径**，
      两行靠左侧名称区分
- [ ] **无 tmux 降级**（可选）：把 `tmuxTerminals.tmuxPath` 改成一个
      不存在的路径 → 所有圆点变 ⚪，点击仍能开终端并 `cd` 到目录

## v2 增补项（排序 / 批量 / 模型切换 / 杀会话）

- [ ] **拖拽排序持久**：在「终端清单」里把某条拖到别处 → 顺序变化，
      且 `tmux ls` 输出**不变**（排序绝不触发任何 tmux 操作）。重载窗口
      后顺序仍保持。
- [ ] **杀会话 → 新建而非「又连上」**：右键条目「杀掉远端 tmux 会话」
      → 确认 → 对应终端面板关闭、该条目显示「无会话」；**再点一次该条目
      是新建会话**（预设命令重跑），而不是又接回一个已消失的会话。
- [ ] **运行中的 claude 切模型**：在条目对应的终端里跑起 `claude`，
      右键该条目「设置模型…」选一个 → 会话里的模型立即生效，条目的
      tooltip「模型」字段更新为该模型。
- [ ] **运行中的非 claude 切模型 → 必须拒绝**：在该终端里运行
      `sleep 600`，右键「设置模型…」→ 必须弹出「已拒绝」错误
      （前台进程不是 claude），且 `sleep` 进程不受影响。
- [ ] **批量设为直连**：在「批量操作」面板选中 2 条 → 标题栏「设为直连」
      → 这两条的徽标颜色变橙（🟠 direct）。

## 会话身份增补项（**必须手动** —— 自动测试覆盖不到）

> **为什么只能手动**：`test/e2e-harness.js` 是把 `TerminalManager` 直接
> `new` 出来跑的，**从不加载 `src/extension.ts`**（单测同理）。所以本批加在
> extension.ts 里的 **5 个 reconcile 触发点**、以及活动采样闸门，
> **没有任何自动化覆盖**，只能由人在这里走一遍。
>
> 下列观察点都对准本批修的两个症状：
> **(a)** 在 claude 里 `/new` 换了会话（或手动改绑）后，条目**存着**的对话
> 要跟着终端走 —— 修复前它一直停在换掉的那条上；
> **(b)** 第三级「任务名」要在面板一可见就出现（**约一拍 ≈900ms** ——
> 该拍长源自 `extension.ts` 的 `ACTIVITY_POLL_INTERVAL_MS`，**是代码推断、
> 未经实测**），而不是等默认 **10s** 的存活轮询。

**两个观察窗口**（每条都要用，先记住怎么看）：

- **条目存着哪条对话**：鼠标悬停在条目上，tooltip 里以「对话：」开头的
  那一行显示的就是条目**当前存着**的对话 id —— 只给前 8 位、后面跟 `…`，
  并附「启动时接回这条」。那一行若显示「未绑定」，即表示没存。
- **第三级任务名**：条目（二级）**下面再多出一层**、标签即任务名的节点。
  **没有这一层** = 此刻没有可显示的任务名。它优先取 tmux pane title 解析出
  的任务名，解析不出时才回退到**绑定对话的 aiTitle** —— 两种来源都会让它
  出现/变化。第三级只读内存缓存，**重载窗口即清空**（想让它从「没有」开始，
  先重载窗口）。

### reconcile 的触发点（六条；源码 `extension.ts:138-140` 枚举的是**五个**，「展开树 / 面板可见」在下面拆成了 ④⑤）

- [ ] **① 扩展激活**：先确认这条条目**已绑定**一条对话（悬停时「对话」行
      不是「未绑定」）、且它的 tmux 会话里 claude 正在跑。然后用
      `Developer: Reload Window` 重载窗口，**不碰 ⟳、不点任何条目**，
      等约一秒：条目下应已出现第三级；悬停条目的「对话」行，短 id 应与
      终端里 claude 正用着的那条一致（若重载前刚 `/new` 过，这里应已
      自动跟上，无需手动操作）。
- [ ] **② ⟳ 刷新**：先在终端里让 claude `/new` 换一条会话并随便说两句
      （或用下面的「手动改绑」改一次）。回侧边栏点标题栏 ⟳「刷新状态」。
      **命令返回时（转圈结束）**悬停条目，「对话」行**已经**变成终端当前
      那条 —— 这一步是同步的，不需要再等。第三级随下一拍刷新。
- [ ] **③ 点击条目**：在 ② 之后，右键该条目「杀掉远端 tmux 会话」→
      圆点转 ⚪ → 点击条目重建。**接回/重建的必须是当前那条新会话**
      （不是 `/new` 之前被放弃的那条）；悬停条目「对话」行与之一致。
- [ ] **④ 面板变为可见**：把侧边栏切到别的视图（如「资源管理器」），再切回
      「Tmux Terminals」。**约一拍（≈900ms）内**第三级就应出现/刷新
      （该拍长源自 `ACTIVITY_POLL_INTERVAL_MS`，未经实测）；
      **不应**拖到默认 10s 的存活轮询才动。
      *（更尖的判据，可选）：临时把 `tmuxTerminals.pollInterval` 调大到
      `30000`，重载窗口后重复本步 —— 第三级**仍应在约 1s 内**出现/刷新。
      若它跟着变成 30s 才动，说明它走的是存活轮询而不是活动采样闸门。*
- [ ] **⑤ 展开节点**：把已展开的文件夹节点**折叠**、再**展开**；或展开一个
      默认折叠的节点。展开这一下本身即触发 reconcile —— 悬停条目的
      「对话」行应立刻跟随终端当前会话，第三级随下一拍出现。
- [ ] **⑥ 切 profile**：右键条目 →「切换直连/中转」，把它从 `ccr` 切到
      `direct`（或反向）。**切之前先在这条会话里 `/new` 换一条对话**，
      再执行切换。切完悬停条目：tooltip 的「profile：」行应已翻转
      （🔵 ccr ↔ 🟠 direct），「对话：」行应是 `/new` 之后那条**新**对话
      —— 切 profile 会先 `/exit` 再用 `--resume` 重启 claude，
      **绝不能接回被放弃的旧对话**。
      （`restartClaude` 正是在 `--resume` **之前**先 reconcile，
      所以这条路径正是「绑定一旦陈旧就接回旧对话」的现场。）

### 核心：绑定跟随 + 手动改绑不被冲掉

- [ ] **★ `/new` 之后绑定自动跟随**（本批的主症状）：
      在条目对应的终端里跑起 claude → 悬停条目记下「对话」短 id（记作 **A**）
      → 在 claude 里输入 `/new` 开一条新对话，随便说两句 → 回侧边栏点 ⟳
      → 悬停条目，「对话」应变成 **B（≠ A）**，且 B 是该目录下**最新**的
      那条对话（右键「选择要接回的对话…」的列表里，最新一条就是它）。
      **修复前的表现**：这里仍显示 A，且恢复时会接回被放弃的 A。
- [ ] **★ 手动改绑要守得住**：右键条目 →「选择要接回的对话…」→ 选一条
      **不是**最新、也不是终端当前在用的对话（记作 **X**）→ 悬停条目应显示
      X 的短 id。再点 ⟳、并把侧边栏切走再切回。**X 必须保持不变** ——
      手动选择不能被下一轮观测冲掉。
      （例外：若这期间终端里真的又 `/new` 过，那属于「终端换了会话」，
      X 应当让位给新会话 —— 那正是上面那条的行为。）

## 选择框噪音 / 首启参数 / 三级刷新（2026-09-16 增补）

> 同样只走手动 —— 单测覆盖了纯函数层（`isSyntheticUserText`、
> `parseConversationHead`、重试冷却与通知），但「QuickPick 里到底显示成什么样」
> 和「首启那条命令行长什么样」都要真机看一眼。

- [ ] **合成包裹消息不再进选择框**：在任一终端里先输入 `/clear`（或让该会话
      以任何斜杠命令开头）→ 再右键条目 →「选择要接回的对话…」。列表里**不应**
      出现 `<local-command-caveat>`、`<command-name>` 这类尖括号文本；该会话
      那行要么是它**真正的**首条提问，要么是「（无首条消息）」。整列扫一遍确认。
- [ ] **★ 选择框必须能弹出来**：右键任一已打开过的条目 →「选择要接回的对话…」
      → 列表**必须立刻出现**。**修复前的表现**：命令直接报错
      `CANNOT use API proposal: quickPickItemTooltip`，列表根本不弹（原因：
      `QuickPickItem.tooltip` 是 proposed API，正常安装的扩展用不了）。
      同一处一旦抛错，老条目首次接回、全部恢复、切 profile 也都会跟着失败 ——
      它们走的是同一个选择框。
- [ ] **候选显示的是一行，内容是首条提问的原文**：列表里每条候选是
      `时间 · 首条用户消息原文 · 体积`，**只有这一行**——没有第二行、
      也没有悬停浮层（`QuickPickItem.tooltip` 是 proposed API，正常安装的
      扩展用不了，用了会让整个选择框抛错）。原文**不压缩语义**，只把换行
      压成空格；超长由 VS Code 按行宽自己截断成 `…`。挑一条你记得的会话，
      确认显示的就是你当时敲的那句话（而不是被改写过、或截到 60 字的版本）。
- [ ] **「+」新建条目首启不带会话参数**：标题栏 `+` 建一条新条目 → 打开它。
      **不应**再弹「绑定的对话还没有记录…」那条提示；终端里起来的是一条全新
      对话（不是接回任何历史）。聊一句之后悬停该条目：tooltip 的「对话」行
      短 id 应当**变成**这条新对话的 id —— 这说明绑定是被观测回写的，而不是
      出生时钉死的那个。
- [ ] **★ 三级任务名会自己出现，不用点 ⟳**：在某个条目里 `/new`（此时第三级
      会消失，正常）→ **之后不要点任何条目、也不要点 ⟳**，就在这个终端里聊两
      三个来回等 claude 写出 `ai-title`。最多约 **35 秒**（存活轮询 10s +
      缓存内 25s 冷却，最坏情况各差一拍）内，第三级应当**自己**冒出来，并且
      二级是**展开**状态。若不出现，先确认 `tmuxTerminals.pollInterval` 没被
      设成 0，且面板当时是可见的（隐藏时不轮询）。

## 存活轮询自动观测（2026-09-16 增补）

> 本批把 reconcile 挂上了 10 秒的存活轮询（`src/extension.ts` 的 `poll()`）——
> 从此**不碰面板也会自动观测并改绑**。这三条都只能手动看：`extension.ts`
> 不参与任何自动化测试（见上一节的说明）。

- [ ] **★ 完全不碰面板，三级自己出现**（本批主症状，必须走这条）：
      标题栏 `+` 新建一条条目 → 点击它打开终端 → 在终端里向 claude 提两三个
      问题（聊到它写出 `ai-title`）→ **之后完全不碰侧边栏**：不点条目、不点
      ⟳、不折叠也不展开任何节点，连鼠标都不要移到侧边栏上。
      等约 **10~35 秒**（存活轮询 10s + 缓存内 25s 冷却，最坏情况各差一拍），
      观察**看哪里**：条目（二级）下面。**应该看到**：多出一层三级，标签是
      **你刚在聊的那个任务**的名字，而不是重载窗口前的旧名字、也不是没有。
      **不该看到**：三级一直空着、或三级显示的是别的（旧的）任务名。
      **修复前的表现**：三级永远不出现 —— 绑定停在新建时预分配的幽灵 id 上，
      回退链每 25 秒去重读一个不存在的文件。
      （若没出现，先确认 `tmuxTerminals.pollInterval` 没被设成 `0`，且侧边栏
      当时**可见** —— 面板隐藏时这一拍不跑，属正常。）
- [ ] **标题栏没有常驻进度条**：保持侧边栏面板可见，盯住视图标题栏那行约
      半分钟。**应该看到**：标题栏是静止的（只有图标），没有一直在转的进度条。
      **不该看到**：标题栏上挂着一个永不停的 spinner —— 那说明某一拍被拖成了
      「永远没跑完」。本批新增的 reconcile 与既有的存活查询共用一次轮询，
      正常时它几分之一秒就结束。
- [ ] **连点几个条目不卡顿**：快速连续点击 3~4 个不同条目（每个点完立刻点
      下一个，不等终端起来）。**应该看到**：每点一个，对应的终端**立即**被
      切到前台。
      **不该看到**：点完当下没反应、过几秒才把刚才点过的终端**一次性全跳
      一遍** —— 那说明点击被排进了某个串行的队列里干等（观测应当在点击返回
      前就结束，不该把按键攒起来补发）。
